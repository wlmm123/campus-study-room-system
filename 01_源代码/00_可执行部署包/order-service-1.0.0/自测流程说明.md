# 预约订单流转子系统（8083）· 本机自测与冒烟全流程

> 适用：成员6 在节点B 部署后，从零验证 8083 的核心状态机、内部接口及跨节点连通性
> 环境：JDK 11、MySQL 8.0（节点B 本机 3306）、`order_db` 已执行 `init_nodeB.sql` 初始化
> 产出物目录：`00_可执行部署包/order-service-1.0.0.jar`

---

## 0. 前置检查（30 秒）

打开 CMD，依次执行：

```bat
chcp 65001
netstat -ano | findstr ":8083"
```

**期望**：最后一条**没有任何输出**（说明 8083 端口空闲）。

| 现象 | 处理 |
| --- | --- |
| 有 `LISTENING  <PID>` 输出 | 端口被占。执行 `taskkill /F /PID <PID>` 杀掉进程 |
| 连不上数据库 | 检查节点B的 MySQL 服务是否启动，密码是否配在 `config/application.yml` |

---

## 1. 启动服务

进入 `00_可执行部署包` 目录（确保 `order-service-1.0.0.jar` 与 `config` 文件夹在此同级），在 CMD 执行：

```bat
java -jar order-service-1.0.0.jar --spring.config.additional-location=./config/
```

**期望输出**：
```
🚀 校园自习室 - 订单流转子系统 (8083) 启动成功！
Tomcat started on port(s): 8083 (http)
```

> ⚠️ **排错**：若报错 `Could not resolve placeholder 'XXX'`，说明启动命令没加 `--spring.config.additional-location=./config/`，或者 config 目录没建对。

> 准备变量（在 CMD 中执行，后续指令可以直接复制，不用替换长 Token）：

## 3. 冒烟测试二：核心状态机正向流转（需启动 8082 配合）

**步骤 1：正常预约（请把 startTime 换成比当前时间晚几分钟的时间）**
```bat
curl -X POST -H "Authorization: Bearer %STU%" -H "Content-Type: application/json" -d "{\"seatId\":1,\"startTime\":\"2026-11-09 10:00:00\",\"durationHours\":2}" http://localhost:8083/api/orders/reserve
```
*   **预期**：返回 `code:200`，记下返回 JSON 中的 `orderId`（后续假设叫 `<OID>`）。

**步骤 2：签到（到了开始时间后再执行）**
```bat
curl -X POST -H "Authorization: Bearer %STU%" http://localhost:8083/api/orders/<OID>/sign-in
```
*   **预期**：返回 `code:200`。

**步骤 3：暂离**
```bat
curl -X POST -H "Authorization: Bearer %STU%" http://localhost:8083/api/orders/<OID>/temp-leave
```
*   **预期**：返回 `code:200`。

**步骤 4：暂离返回**
```bat
curl -X POST -H "Authorization: Bearer %STU%" http://localhost:8083/api/orders/<OID>/return-back
```
*   **预期**：返回 `code:200`。

**步骤 5：主动离开**
```bat
curl -X POST -H "Authorization: Bearer %STU%" http://localhost:8083/api/orders/<OID>/leave
```
*   **预期**：返回 `code:200`。

## 4. 冒烟测试三：边界拦截与状态机异常（契约强制要求）

**场景 1：验证 1008 时段重叠**
*(前提：刚才已经下过一个 10:00-12:00 的单，现在再下一个重叠时间的)*
```bat
curl -X POST -H "Authorization: Bearer %STU%" -H "Content-Type: application/json" -d "{\"seatId\":2,\"startTime\":\"2026-11-09 11:00:00\",\"durationHours\":2}" http://localhost:8083/api/orders/reserve
```

**场景 2：验证 1002 参数越界**

**场景 3：验证 1003 非待签到状态取消**

```bat
curl -X POST -H "Authorization: Bearer %STU%" http://localhost:8083/api/orders/<OID>/cancel
```
*   **预期**：返回 `code:1003`。

## 5. 冒烟测试四：定时任务与分布式容错（高光亮点）

**场景 1：手动触发超时扫描**
*(如果在测试时造了过期没签到的单，敲这个指令会把它释放)*
```bat
curl -X POST -H "X-Internal-Token: %TOKEN%" http://localhost:8083/api/internal/orders/batch-handle-timeout
```
*   **预期**：返回统计 JSON，对应订单状态变为 `超时释放`。

**场景 2：验证 8082 宕机兜底**
*(先让成员2把 8082 停掉，然后尝试下单)*
```bat
curl -X POST -H "Authorization: Bearer %STU%" -H "Content-Type: application/json" -d "{\"seatId\":1,\"startTime\":\"2026-11-09 15:00:00\",\"durationHours\":2}" http://localhost:8083/api/orders/reserve
```
*   **预期**：返回 **`code:1007`**（外部依赖调用失败），**绝对不能返回 HTTP 500 或崩溃**。

**场景 3：验证 8084 宕机容错**
*(让成员4停掉 8084，制造一个超过签到时间的单，等 2 分钟)*
*   **预期**：订单状态保持 `待签到`，座位不释放（锁死）。**让成员4重启 8084，等 1 分钟**，再次调用 `batch-handle-timeout`，订单被自动释放。

## 6. 常见报错对照表

| 报错信息 | 原因 | 处理方式 |
| --- | --- | --- |
| `Communications link failure` | 节点B MySQL 没起 / 密码错 | 检查 `config/application.yml` 里的用户名和口令 |
| `Unknown database 'order_db'` | 库没建 | 在节点B执行 `init_nodeB.sql` 脚本 |
| 跨服务调用报错 `1005` | `internal.token` 不一致 | 检查四端 `internal.token` 是否与群内统一下发的一致 |
| 登录或外部访问报错 `401` | `jwt.secret` 不一致 | 检查四端 `jwt.secret` 是否完全一致 |
| 跨服务调用报错 `1007` | 下游 8082/8084 挂了或 IP 填错 | 检查对方的服务是否启动，及配置文件的 IP |
```
