## 一、环境依赖
1. **JDK 11**
2. **MySQL 8.0**（已创建 `order_db` 数据库，且已在节点B执行 `init_nodeB.sql`）

## 二、目录结构
请确保解压后的文件结构如下（必须保证 jar 包和 config 目录在同级）：
```text
├── order-service-1.0.0.jar   (后端可执行程序)
├── config/
│   └── application.yml       (外置配置文件，用于覆盖 jar 包内配置)
└── 启动说明.md               (本文件)
```

## 三、启动命令
请在当前目录（与 jar 同级）打开终端，执行以下命令：
```bash
java -jar order-service-1.0.0.jar --spring.config.additional-location=./config/
```

> ⚠️ **参数说明**：
> 1. 参数是 `additional-location`（追加语义），**绝对不能写成** `location`（覆盖语义会让 jar 内默认配置全失效，导致启动崩溃）。
> 2. 末尾的 `./config/` 代表读取当前目录下 `config` 文件夹中的 `application.yml`。如果路径不对，会报错 `Could not resolve placeholder`。

## 四、部署与配置检查清单 (非常重要！)
在启动前，请务必检查 `config/application.yml` 中的以下配置项：
1. **数据库密码**：检查 `spring.datasource.password` 是否与节点B本地 MySQL 密码一致（模板中默认兜底为 `123456`）。
2. **鉴权密钥**：`jwt.secret` 与 `internal.token` 必须与节点A（8081/8082）和节点B的 8084 **完全一致**。如果四端不一致，会直接导致所有跨服务调用报错 401 或 1005。
3. **跨节点 IP**：
   - `remote.seat-service-url`：必须指向节点A（宿主机）的真实局域网 IP（如 `http://10.165.59.231:8082`）。
   - `remote.notify-service-url`：必须指向节点B的真实局域网 IP（如 `http://192.168.56.101:8084`）。
4. **时区**：确保节点B的 Ubuntu 虚拟机、JDK、MySQL 时区均为 `Asia/Shanghai`。

## 五、验证服务是否启动成功
1. **看控制台**：终端打印出 `🚀 校园自习室 - 订单流转子系统 (8083) 启动成功！` 字样。
2. **测鉴权**：打开 Postman，访问 `GET http://localhost:8083/api/orders/my-list`。如果不带 Token 访问，返回统一 JSON 且提示 `401`（Token缺失），说明服务已启动且 JWT 拦截器生效。
3. **测内部接口**：在 Postman 访问 `POST http://localhost:8083/api/internal/orders/batch-handle-timeout`，并在 Header 带上 `X-Internal-Token: campus_studyroom_internal_2026_5d8e2f1a`。如果返回 `200` 及统计 JSON，说明内部鉴权与定时任务链路正常。

## 六、日志与常见排错
- **启动报错 `Could not resolve placeholder 'JWT_SECRET'`**：说明启动命令没加 `--spring.config.additional-location=./config/`，或者 `config` 文件夹名字拼错了，导致没有读到外置配置。
- **连不上数据库 (`Communications link failure`)**：检查节点B的 MySQL 是否已启动，以及 `application.yml` 里的账号密码是否正确。
- **服务调用报错 `1005`**：检查四端的 `internal.token` 是否完全一致。
- **服务调用报错 `401`**：检查四端的 `jwt.secret` 是否完全一致。
